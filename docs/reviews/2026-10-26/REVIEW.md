# 전체 코드 검사 결과 — 2026-10-26

## 결론

앱 전체에 문제가 없다고 판단할 수 없다. 앱 코드 수정 없이 실행한 임시 재현 테스트에서 기존 기능의 결함 4개가 확인되었다. 동일 테스트는 문의하기 추가 전 커밋 `18d47db` 사본에서도 동일하게 실패했다. 문의하기 전용 테스트 3개는 통과했다.

## 검사 범위와 방법

- lib/의 Dart 소스 전체, Android MainActivity와 Gradle/Manifest 설정, 저장소의 테스트, macOS의 기본 Swift 파일을 읽었다.
- 현재 작업본 전체를 `flutter analyze --no-pub`로 검사했다.
- HEAD의 lib/test/pubspec/analysis_options/assets를 임시 폴더에 추출하고, 동일한 설치 패키지 설정으로 수정 전 사본을 분석했다. 작업본을 되돌리거나 수정하지 않았다.
- 경고 코드·파일·행·열을 대조했다. 사용설명 파일의 import 추가 때문에 생성자 권고 위치만 7행에서 8행으로 이동했고, 나머지는 동일했다.
- 저장소의 전체 Flutter 테스트를 실행했다.
- SharedPreferences, 파일 선택기, 에셋 로딩을 모의 처리한 임시 테스트로 결함 4개를 재현했다. 사용자 휴대폰의 실제 데이터에는 접근하지 않았다.
- 이 재현 테스트를 수정 전 커밋 사본에서도 실행해 같은 결과를 확인했다.
- 성장표 JSON 두 파일의 시리즈 존재 여부, 점 형태, 월령 순서를 검사했다. 2017: 42개 시리즈/9,240점, WHO: 42개 시리즈/8,078점에서 검사한 구조상 이상은 없었다. 원본 의학 자료와 값의 정확성을 대조한 검사는 아니다.
- 문의하기가 포함된 동일 앱 소스의 Android 디버그 APK 빌드는 앞선 단계에서 성공했다. 이번 감사에서는 앱 소스를 변경하지 않아 중복 빌드는 하지 않았다.

## 재현으로 확인한 기존 결함

### 1. [P1] 손상된 백업으로 정상 성장 기록을 덮어쓸 수 있음

- 위치: lib/backup_manager.dart:154–172
- 외부 JSON의 schema와 profiles의 최상위 자료형만 확인하고, 각 성장 기록 문자열이 유효한 JSON 목록인지 검증하지 않은 채 저장한다.
- 재현: 정상 성장 기록이 저장된 child1에 대해 schema=2, 정상 프로필, growthByChildId.child1=`not-valid-json`인 백업을 선택했다.
- 기대: 백업 거부 및 기존 기록 유지.
- 실제: 예외 없이 정상 기록이 `not-valid-json`으로 덮어써졌다.
- 수정 방향: 모든 프로필/기록의 구조·자료형·ID·값 검증을 쓰기 전에 완료하고, 저장 실패 시 원복하는 절차를 마련한다.

### 2. [P2] BMI 자동 계산 후 키·체중을 변경하면 이전 BMI가 저장됨

- 위치: lib/child_growth_input.dart:85–90, 114–120; 수정 화면에도 유사한 값 우선 처리 존재(lib/child_growth_list.dart:220–225).
- 재현: 키 100, 체중 20으로 자동 계산한 뒤 체중만 25로 바꾸고 저장했다.
- 기대: 자동 계산값은 현재 입력값에 맞춰 25로 저장.
- 실제: 키 100, 체중 25, BMI 20으로 저장.
- 원인: 자동 계산 결과도 수동 입력처럼 우선 사용하며 키/체중 변경 시 무효화하지 않는다.
- 수정 방향: 자동·수동 값을 구분하고, 자동 모드에서는 저장 시 현재 키/체중으로 재계산한다. 수동 BMI 보존 정책도 명확히 해야 한다.

### 3. [P2] 같은 월령에 체중만 추가하면 기존 키 측정점이 그래프에서 사라짐

- 위치: lib/child_growth_chart.dart:261–280, 533–548
- 재현: 36개월 2023-01-01에 키 100/체중 20, 다음 날 같은 월령에 체중 21만 저장했다.
- 기대: 키 그래프에는 이전의 유효한 키 100이 유지됨.
- 실제: 월령별로 최신 기록 전체 하나만 남겨 키가 null이 되고, 키 그래프에 해당 점이 없어졌다.
- 저장소의 원본 기록은 유지된다. 그래프 표시 누락이다.
- 수정 방향: 키·체중·BMI별로 유효한 최신 값을 선택한다. 같은 날짜 중복 입력 시 우선순위도 정한다.

### 4. [P2] 표준도표 로딩 중 화면을 떠나면 폐기된 화면을 갱신함

- 위치: lib/page_standard_growth_chart.dart:85–95
- 재현: 에셋 로딩을 지연시키고 화면을 제거한 뒤 로딩을 완료했다.
- 실제: `setState() called after dispose()` 예외가 발생했다.
- 성장 그래프의 _loadEntries/_loadStandard에도 await 이후 mounted 확인 없이 setState하는 경로가 있다(lib/child_growth_chart.dart:284–336). 이 유사 경로는 소스 검토 결과이며 별도 재현하지 않았다.
- 수정 방향: 비동기 완료 이후 mounted 확인 및 오류 경로 보호를 적용한다.

## 추가로 확인한 검증 문제 및 실패 처리 위험

### 기존 전체 테스트 실패

test/widget_test.dart:12는 실제 앱에 없는 숫자 0과 카운터 증가를 검사하는 기본 예제다. 전체 실행 결과는 3개 통과/1개 실패였다. 3개는 문의하기 테스트다. 기본 예제를 앱의 실제 주요 흐름 검증으로 교체해야 한다.

### [P2] 광고 표시 실패 시 화면 이동이 끝나지 않을 위험 — 소스 검토

lib/ad_service.dart:432–448에서 Future를 반환하는 AdMob show와 Meta showInterstitialAd를 await하지 않고, 별도 콜백 완료만 기다린다. AdMob의 비동기 예외는 바깥 try/catch로 잡히지 않을 수 있고, Meta의 false 반환도 검사하지 않는다. 표시 실패 뒤 종료 콜백이 오지 않으면 화면 이동의 await가 끝나지 않을 수 있다. 설치된 SDK의 함수 반환형을 직접 확인했으며, 실제 광고 SDK 실패 상황은 재현하지 않았다. 광고를 먼저 표시한 뒤 화면 이동하는 기존 순서는 유지하면서 실패 완료 처리를 보완해야 한다.

### [P2] 기록 저장 실패를 호출자에게 전달하지 않음 — 소스 검토

lib/child_growth_list.dart:99–110은 저장 예외를 안내한 뒤 정상 반환한다. 삭제 호출부(137–141)는 화면에서 기록을 먼저 제거하고, 저장 실패 여부와 무관하게 삭제 완료 메시지를 표시한다. 저장 예외가 발생하는 기기 상황에서는 표시와 저장소가 달라질 수 있다. 실제 디스크 쓰기 실패를 주입한 재현은 하지 않았다. 저장 성공 여부 전달과 실패 시 UI 원복이 필요하다.
